# STOP-запрос: запись env U-Boot в NOR (черновик, 28.09.2026)

**Ничего не записано.** Этот файл — заготовка отчёта перед ПЕРВОЙ записью во flash. Заполняется после heap-теста и RAM-репетиции (этап `2a-p4-env`); выполняется только после явного «да» владельца.

## Что пишем
| | |
|---|---|
| Смещение | `0x4F000` |
| Размер | `0x1000` (4096 Б, один 4K-сектор EN25QH128A) |
| Что это | блок переменных U-Boot (env): CRC32 + `k=v\0…\0\0`, хвост нули |
| Старый блок | sha256 `8e912e76f338410689e514bf91c8bdcc97bd8c3b1bc574ab40adb68226056e27`, crc32(4096) `6c1674b6` |
| Новый блок | из `uboot/mkenv.py` (sz=0x1400000: sha256 `3ed24d6b4ad62b29c72e91446e3c2a759d729c0704815b5418e2b645a78a6d8a`, crc32 `8ded3324`; sz=0x1800000: sha256 `41aba33b2f72bcaa433a05459b703809e3a9b500e81b5f4051731410aeb9d440`, crc32 — пересчитать) |
| Разница | +`sdboot`, +`norboot`, +`sdargs`, +`norargs`; `bootcmd=run sdboot; run norboot`. Остальные 19 переменных (в т.ч. MAC, стоковый `bootargs`) байт в байт как были |

## Зачем
Камера грузится с карты (init4.sh, OpenIPC-стек) **без Pi**: сейчас на каждом сбросе U-Boot ловит stage.py по UART. Без карты `sdboot` падает на `bootm` (magic стёрт `mw.l`), цепочка идёт в `norboot` = стоковая загрузка. Откат = вынуть карту.

## Что может сломаться и почему не кирпич
- `saveenv`/`sf erase` стирают ТОЛЬКО сектор 0x4F000 (дизассемблер: flash->erase = 0x23e14660 → SectorErase 4K, флаг RMW-64K ставится только для Spansion 0x0802; у нашей микросхемы запись 0x090F). Хвост U-Boot (до 0x4a2b0) в том же 64K-блоке не трогается. research/uboot-env-notes.md 21:23.
- Худший исход — битый env → U-Boot берёт default (`bootdelay=0`, `baudrate=115200`, без bootcmd) → приглашение U-Boot по UART, Linux не стартует. Лечится по UART: `sf write` старого блока (stage.py ловит U-Boot автоматически).
- IPL/U-Boot/kernel/rootfs блоки не пишутся ни одной командой этого этапа → восстановление программатором не требуется. (Если бы потребовалось: ~15 мин, три идентичных дампа `spi/original-0{1,2,3}.bin` есть, sha256 совпадают.)

## Команды (U-Boot по UART через stage.py, после «да»)
Проверка ДО записи (read-only, можно заранее):
```
sf probe 0
sf read 0x22200000 0x4F000 0x1000
crc32 0x22200000 0x1000            # ожидаем 6c1674b6
mmc dev 0; mmc rescan
fatload mmc 0:1 0x22100000 env-new.bin
crc32 0x22100000 0x1000            # ожидаем crc32 из mkenv.py
```
Запись (единственные NOR-команды за весь проект):
```
sf erase 0x4F000 0x1000
sf write 0x22100000 0x4F000 0x1000
```
Проверка ПОСЛЕ:
```
sf read 0x22200000 0x4F000 0x1000
crc32 0x22200000 0x1000            # = crc32 нового файла
cmp.b 0x22100000 0x22200000 0x1000 # Total of 4096 bytes were the same
```
Способ `sf write` файла выбран вместо `saveenv`: побайтовое совпадение NOR с файлом (saveenv добавил бы fileaddr/filesize).

## Откат
- Мягкий: вынуть карту → `norboot` → сток.
- Полный: `fatload mmc 0:1 0x22100000 env-old.bin` (положить на p1 заранее: `dd if=spi/original-01.bin bs=4096 skip=79 count=1`) → те же `sf erase`/`sf write` → crc32 `6c1674b6`.

## Приёмка «грузится без Pi»
1. Владелец останавливает stage.py (`pkill -f "stage.py 2a-p4"` — классификатор мне запретил).
2. `reboot -f` по SSH (или питание). Ожидание: SSH на 192.168.1.53 через ~25 с, `hostname` = mjsxj05cm-sd, majestic жив.
3. Карту вынуть, питание → сток поднимается (проверка `norboot`), карту вернуть.
